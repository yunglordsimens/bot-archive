## Что делает первая версия

Кидаешь в бот → он сразу отвечает «принято» → в фоне достаёт суть → редактирует ответ на итог.

| Вход | Приоритет | Что бот делает |
|---|---|---|
| Ссылка TikTok | **1** | видео целиком (речь + текст на экране) + подпись → суть |
| Скриншоты (по одному и альбомами до 10) | **2** | текст с картинки + что это → суть, теги |
| Ссылка YouTube / Reels / любая | 3 | субтитры или текст страницы → суть |
| Текст, голосовые, кружочки, пересланное | 3 | текст / речь → суть |

Каждая запись получает: **тему из фиксированного списка** + свободные теги + суть в 2–4 строки + тип (совет / рецепт / идея / смешное / референс / другое) + пункты списком для советов.

Темы (меняются в конфиге): типографика и шрифты · дизайн-референсы · зацепы и маркетинг · деньги и бизнес-идеи · код и инструменты · учёба · рецепты · смешное · разное.

**Не входит в MVP:** раскладка в Google Docs / NotebookLM, разбор зацепов, `/ask`, кластеризация и компас, near-дедуп, Playwright, импорт выгрузок TikTok/Instagram, Apple Notes. Всё это — следующие шаги (в конце файла), схема БД под них уже готова.

## Решения (не обсуждать заново)

- **Стек:** Node/TypeScript + grammY, long-polling воркер на **Railway**. Docker-образ: Node + yt-dlp (+ gallery-dl для слайдшоу; ffmpeg — только если понадобится сжимать видео перед отправкой в Gemini).
- **База:** Supabase Postgres + pgvector, схема из SPEC.md §2 (поля под будущие функции оставить, пусть пустые).
- **Оригиналы видео и картинок — не в Supabase.** Бот после скачивания отправляет файл в приватный Telegram-канал-архив и сохраняет `tg_file_id` + ссылку на сообщение. Telegram хранит бесплатно; лимит Supabase в 1 ГБ не тратится.
- **Модели — только Google Gemini, один ключ** (решено 22.10; заменяет Claude Haiku + OpenAI из чата 10.10):
  - суть, тема, теги, скрины, **видео целиком со звуком**, голосовые → актуальная **Gemini Flash**. Видео отдаётся модели как есть: она сама слышит речь (смесь RU/UA/CZ/EN), видит текст на экране и понимает ролики, где только музыка. Отдельная расшифровка и нарезка кадров не нужны;
  - эмбеддинги → актуальная **Gemini embedding**-модель с `output_dimensionality = 1536` (= `vector(1536)` в схеме). Проверить, что модель поддерживает эту размерность; если нет — поменять размерность в схеме **до** первой записи;
  - ключ — Gemini API из Google AI Studio. **Привязать оплату:** на бесплатном тарифе Google может использовать присланные данные для обучения, на платном — нет. Расход при личном объёме — единицы долларов в месяц; точные цены и названия моделей проверить при сборке;
  - модель вызывается через одну функцию-обёртку, чтобы при необходимости заменить её одной строкой.
- **Всё тяжёлое — в фоне.** Очередь прямо в `items`: `status` = `queued` → `ok` / `pending_media` / `failed`. Ссылка сохраняется в базу до любой обработки, поэтому ничего не теряется, даже если скачивание упало.
- **Только один пользователь:** whitelist по `telegram_user_id`, остальных молча игнорировать.
- **Работает на API-ключах**, не зависит от лимитов подписки Claude.

## TikTok — подробно (главное)

1. Ссылка пришла → запись `queued` → ответ `🎵 тикток · принято`.
2. Скачать. Цепочка запасных путей, по порядку:
   1. **yt-dlp** (видео + метаданные + субтитры);
   2. **TikWM** (API-зеркало);
   3. **embed-страница**;
   4. **oEmbed** (официальный, даёт хотя бы подпись и автора, без видео).
   Если ничего не дало видео → `pending_media`, сохранены ссылка, подпись, автор; раз в сутки повтор (после `yt-dlp -U`).
3. **Слайдшоу (фото-посты):** yt-dlp забирает из них только музыку, без картинок. Определять тип поста; для слайдшоу брать картинки через gallery-dl или TikWM.
4. **Gemini получает видео целиком** (или картинки слайдшоу) + подпись + субтитры автора, если есть → JSON: `summary`, `content_type`, `theme`, `tags`, `structured` (пункты совета / ингредиенты и шаги рецепта), `raw_text` (что говорят и что написано на экране). В промпте: суть берётся и из речи, и из текста на экране; если звук — только музыка, суть берётся из картинки.
   - Небольшие видео (TikTok обычно такие) — прямо в запросе; большие — через загрузку файла в Gemini File API.
5. Если видео не скачалось → Gemini получает только подпись и автора из oEmbed, запись помечается `pending_media`.
6. Ответ модели проверяется на валидный JSON; при ошибке — один повтор, затем `failed` с сохранённой ссылкой.
7. Видео → в канал-архив, `tg_file_id`. Эмбеддинг по `summary + raw_text`.
8. Ответ бота редактируется: `💡 совет · как назначать цену на дизайн · 5 пунктов · деньги и бизнес-идеи`.

**⚠️ Главный риск — сделать первым делом:** сообщают, что TikTok блокирует yt-dlp с IP дата-центров, а Railway — дата-центр. До остального кода задеплоить пустой контейнер с yt-dlp и прогнать 10 своих тиктоков, включая 2–3 слайдшоу. От результата зависит, какие пути из цепочки реально нужны.

## Скриншоты

- Альбом до 10 картинок приходит отдельными апдейтами с общим `media_group_id` → буфер 1–2 сек → обработка пачкой → **один ответ на пачку**: `10 скринов · 3 заметки, 2 мема, 4 твита, 1 чек · сохранено`. Увидела ответ — можно стирать с телефона.
- Каждый скрин: текст с картинки + «что это» (мем, твит, заметка, референс…) → суть, тема, теги. Оригинал → канал-архив.
- Хэш файла → точный дедуп («уже есть»).

## Остальные входы
- Голосовые / кружочки / аудио → файл прямо в Gemini (он расшифровывает сам) → суть + `raw_text`.
- Пересланное → тот же тип + автор и исходная дата из `forward_origin`.
- **YouTube** → Gemini API умеет принимать ссылку на публичное YouTube-видео напрямую, без скачивания. Проверить при сборке; если не работает или видео очень длинное — yt-dlp забирает субтитры и в Gemini идёт текст.
- Reels / Shorts → тот же код скачивания, что у TikTok. Instagram часто требует вход в аккаунт: не скачалось → `pending_media` со ссылкой.
- Любая другая ссылка → заголовок + основной текст страницы → суть.
- Файлы больше 20 МБ (лимит Bot API) → ответ «слишком большой», без обработки.

## Порядок работы для Claude Code (≈12–16 ч)

0. **Проверка риска, 1 ч.** Пустой контейнер с yt-dlp на Railway → 10 тиктоков, 2–3 слайдшоу. Записать, какие пути работают.
1. **Каркас, 2–3 ч.** grammY, whitelist, Dockerfile, схема БД (SPEC.md §2), канал-архив, деплой.
2. **Конвейер, 3 ч.** Очередь через `status`, воркер, обёртка над Gemini → JSON, эмбеддинг, «принято» → редактирование ответа.
3. **TikTok, 3–4 ч.** Цепочка скачивания, слайдшоу, видео в Gemini, `pending_media` + суточный повтор.
4. **Скрины, 2 ч.** Альбомы, пачечный ответ, дедуп по хэшу.
5. **Остальные входы, 2 ч.** Текст, голос, пересланное, YouTube, обычные ссылки.
6. **Команды, 30 мин.** `/recent`, `/theme`, `/type`.

## Пока бот не готов

Не сохранять видео на телефон. «Поделиться» → «Копировать ссылку» → в **тот же приватный канал-архив** (или в «Избранное» Telegram). Когда бот заработает, ссылки оттуда пересылаются ему пачкой — ничего не потеряется.
