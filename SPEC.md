# SPEC — бот-архив «второй мозг» (единая версия)

> **Начинать сборку с `bot-archive/MVP.md`.** Там короткая версия первой сборки с правками по TikTok (цепочка скачивания, слайдшоу, хранение оригиналов в Telegram, выбор моделей). Этот файл — полная спека на будущее; где они расходятся, для MVP верен MVP.md.

Личный Telegram-бот для одного пользователя. Кидаешь туда **что угодно**: скриншоты, голосовые, пересланные сообщения, тиктоки, куски чатов с ИИ, заметки. Бот расшифровывает, понимает что это, складывает в одну связанную базу, ищет по смыслу и работает как компас: показывает, к чему ты постоянно возвращаешься и что созрело для действия.

Документ для передачи в Claude Code. Объединяет две прошлые версии: «скриншотную» спеку (чат «Я хочу сделать бота в тг куда…», 05.10.2026) и расширение до архива всего подряд (чат «bot Jarvis», 05.10.2026).

**Главная проблема, которую решает бот:** важное разбросано по голосовым в Telegram и Instagram, чатам Gemini/Claude/Qwen, тиктокам, скринам и заметкам. Потом не найти, а переслушивать и перечитывать нет времени. Бот — одно место, куда всё пересылается, и где можно спросить «что я говорила про видео?» и получить ответ со ссылкой на оригинал.

## 0.1 Быстрый старт: «кидаю ссылку → оно само разложилось» (минимальная версия)

Цель первой версии: бот принимает ссылки (TikTok, YouTube, Instagram, любые) и текст, достаёт суть и **раскладывает по темам в Google Docs**, которые подключены к NotebookLM. Всё остальное (голосовые, скрины, компас) добавляется после.

**Почему через Google Docs.** У обычного NotebookLM нет открытого API: бот не может сам добавлять туда источники. Но NotebookLM умеет брать Google Docs из Drive как источник и подтягивать их обновления (кнопка синхронизации у источника). Поэтому бот пишет в Google Docs, по одному на тему, а NotebookLM читает эти документы. Подключить документ в NotebookLM нужно один раз.

**Сортировка в первой версии — по фиксированному списку тем**, а не кластеризацией: кластеризации нужно ≈100 записей. Модель выбирает одну тему из списка + свободные теги. Если ничего не подходит → «Разное». Список тем лежит в конфиге, его можно менять. Черновик:
- Типографика и шрифты
- Дизайн-референсы
- Зацепы и маркетинг (видео ради формы, §3.9)
- Деньги и бизнес-идеи
- Код и инструменты
- Учёба
- Рецепты
- Смешное
- Разное

**Что получается в Drive:**
```
Архив бота/
  Типографика и шрифты.gdoc
  Дизайн-референсы.gdoc
  Зацепы и маркетинг.gdoc
  …
```
Каждая запись дописывается в начало документа своей темы: дата, источник, ссылка, суть (3–5 строк), теги, для видео — главные мысли и разбор зацепа. В Supabase хранится то же самое (для поиска и будущего компаса).

**Шаги:**
1. Telegram: @BotFather → создать бота → токен. *(ты, 5 мин)*
2. Supabase: проект + схема §2. *(может сделать Claude через подключение Supabase)*
3. Google Drive: папка «Архив бота» + по документу на тему. *(может сделать Claude через подключение Drive)* Для бота — сервисный аккаунт Google с доступом к этой папке.
4. Claude Code по этой спеке: бот на Railway, вход «ссылка / текст», yt-dlp (субтитры → иначе аудио → транскрипция), вызов Claude → тема + суть + теги, запись в Supabase и в Google Doc темы. *(1 вечер–день)*
5. NotebookLM: по блокноту на 2–4 главные темы, источник = Google Doc этой темы. *(ты, 10 мин)*
6. Пользоваться: «Поделиться» → бот. Раз в неделю — синхронизировать источники в NotebookLM.

**Ограничения, известные заранее:**
- Instagram по ссылке скачивается хуже всех: yt-dlp часто требует cookies залогиненного аккаунта. Если не скачалось — бот сохраняет ссылку и подпись, а для разбора можно прислать запись экрана.
- TikTok и YouTube обычно работают, но могут ломаться при изменениях платформ (§3.5).

## 0. Принцип: строить фазами, начинать копить сразу

Поиск и компас бесполезны без данных. Поэтому первой выкатывается версия, которая просто **принимает и сохраняет**. База копится, пока строится остальное.

| Фаза | Что | Объём |
|---|---|---|
| **1. Сбор** | Бот принимает все типы входа (§3), расшифровывает, классифицирует, сохраняет. Дедуп. | 1–2 дня |
| **1b. Сложные входы** | TikTok по ссылке, ссылки на чаты ИИ (share-ссылки), разбор зацепа видео (§3.9) | +2–3 вечера |
| **2. Поиск** | `/ask` — вопрос обычным языком или голосом → ответ по базе со ссылками | 1 вечер |
| **3. Темы и компас** | Кластеризация, `/themes`, `/lost` | 2–3 вечера, после ≈100 записей |
| **4. UI** | React-дашборд, граф связей | по желанию |

**Правило:** не начинать Фазу 3, пока в базе нет ≈100 записей. Фазу 4 не начинать, пока ботом не пользуешься каждый день.

## 1. Стек

| Слой | Выбор | Заметки |
|---|---|---|
| Бот | **grammY** (Node/TS), long-polling воркер | Хостинг на always-on: **Railway** (уже используется) или Fly. Не Vercel serverless: обработка видео и vision занимает секунды–минуты, упирается в лимит времени. |
| База | **Supabase Postgres + pgvector** | Метаданные + векторы в одном месте. Дашборд Supabase = UI на первое время. |
| Файлы | **Supabase Storage** | Оригинал сохраняется **всегда**: картинка, аудио, видео. |
| Распознавание речи | Актуальная модель транскрипции через API (OpenAI Whisper / gpt-4o-transcribe или аналог) | **Язык не фиксировать.** Речь — смесь RU / UA / CZ / EN в одной фразе. Автоопределение. Проверить на реальных голосовых до выбора модели. |
| Понимание (vision + текст) | **Claude** (актуальная модель) | Один вызов: что это, суть, тип, теги, структура (для рецептов). Строгий JSON. |
| Эмбеддинги | **Voyage AI** или OpenAI `text-embedding-3-small` | Выбрать одну и **не менять**, иначе старые и новые векторы несравнимы. Мультиязычность обязательна. |
| Разбор видео целиком (картинка + звук) | **Gemini API** (актуальная модель) | Только для разбора зацепа (§3.9). Gemini принимает видео со звуком напрямую и видит, как они сочетаются во времени. Claude видит только отдельные кадры плюс транскрипт, без интонации, музыки и монтажа. Проверить на 5–10 реальных видео, прежде чем закладываться. |
| Скачивание видео | **yt-dlp** + **ffmpeg** | Неофициально, периодически ломается (см. §3.5). |
| Рендер share-ссылок | **Playwright** (headless Chromium) | Страницы чатов Gemini/Qwen рендерятся только с JavaScript. |
| Кластеризация | **HDBSCAN** (Python, батч) | Сам определяет число тем и откидывает одиночный шум. |
| UI (Фаза 4) | Vite + React + `react-force-graph` | |

## 2. Схема БД

```sql
create extension if not exists vector;

create table themes (
  id            uuid primary key default gen_random_uuid(),
  label         text,          -- название твоими словами (генерит LLM)
  synthesis     text,          -- «сквозная линия, которая тебя тут держит»
  next_step     text,          -- конкретный следующий шаг
  item_count    int default 0,
  last_added_at timestamptz,   -- recency
  momentum      real,          -- темп прироста сейчас vs исторический
  status        text,          -- 'recurring' | 'active' | 'dormant'
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

create table items (
  id             uuid primary key default gen_random_uuid(),
  created_at     timestamptz not null default now(),  -- когда попало в бот
  occurred_at    timestamptz,       -- когда это было на самом деле (дата пересланного сообщения, дата тиктока)

  -- откуда
  input_kind     text not null,     -- 'screenshot' | 'photo' | 'voice' | 'audio' | 'video' | 'video_note'
                                    -- | 'text' | 'forwarded' | 'tiktok' | 'link' | 'chat_link' | 'chat_paste' | 'document'
  origin         text,              -- 'telegram' | 'instagram' | 'tiktok' | 'gemini' | 'claude' | 'qwen' | 'apple_notes' | 'other'
  origin_detail  text,              -- имя чата/человека, от кого переслано
  source_url     text,              -- ссылка на оригинал (тикток, share-ссылка чата)
  tg_message_id  bigint,
  tg_file_id     text,

  -- файлы
  media_path     text,              -- путь в Supabase Storage
  media_hash     text,              -- sha256 файла, для точного дедупа
  text_hash      text,              -- sha256 нормализованного текста, для дедупа текстов и ссылок

  -- содержание
  raw_text       text,              -- текст сообщения / OCR / транскрипт / текст страницы
  caption        text,              -- подпись (тикток, фото)
  summary        text,              -- краткая суть от модели
  content_type   text,              -- 'thought' | 'idea' | 'recipe' | 'funny' | 'tip' | 'reference' | 'task' | 'quote' | 'other'
  tags           text[],
  structured     jsonb,             -- например рецепт: {ingredients: [...], steps: [...]}
  save_reason    text,              -- зачем сохранила: 'info' | 'hook' | 'funny' | 'controversial' | 'aesthetic' | 'mixed'
                                    -- угадывает модель, ты поправляешь кнопкой (§3.9)
  hook           jsonb,             -- разбор зацепа для видео (§3.9), иначе null
  hook_embedding vector(1536),      -- эмбеддинг по тексту разбора зацепа: группирует видео по ПРИЁМУ, а не по теме
  my_note        text,              -- твой комментарий «почему зацепило», прикреплённый сразу после пересылки (§3.9)
  language       text[],            -- какие языки встретились

  embedding      vector(1536),      -- размерность = размерность выбранной модели эмбеддингов
  theme_id       uuid references themes(id),
  status         text default 'ok', -- 'ok' | 'pending_media' (видео не скачалось) | 'failed'
  raw_meta       jsonb              -- сырые ответы моделей, длительность аудио и т.п.
);

create index items_created_idx on items (created_at desc);
create index items_kind_idx    on items (input_kind);
create index items_type_idx    on items (content_type);
-- векторный индекс создать после первой заливки данных:
-- create index on items using hnsw (embedding vector_cosine_ops);
```

Связи между записями не храним отдельной таблицей: считаем через ближайших соседей по вектору. Материализовать позже, если понадобится для графа.

## 3. Типы входа (Фаза 1 и 1b)

Общий конвейер для каждого входа:

1. Определить `input_kind` по типу апдейта Telegram.
2. Скачать файл (если есть), посчитать хэш. **Точный дедуп**: хэш уже есть → ответить «уже есть: <суть>, <дата>» и стоп.
3. Извлечь текст (зависит от типа, ниже).
4. Вызов Claude → JSON: `summary`, `content_type`, `tags`, `structured`, `language`. Только валидный JSON без преамбулы.
5. Эмбеддинг по `summary + raw_text` (длинный текст обрезать / разбить, см. §3.6).
6. **Near-дедуп**: косинусная близость > ~0.92 → «похоже на <запись>, сохранила связь» (сохранять всё равно, но помечать).
7. Залить оригинал в Storage, вставить строку в `items`.
8. Короткий ответ в чат: `🎙 голосовое · мысль · «хочу снять видео для…» · сохранено`.

**Ответ должен быть коротким.** Бот — склад, а не собеседник. Никаких длинных разборов при сохранении.

### 3.1 Скриншоты и фото
- Vision-вызов: OCR + понимание, есть ли внутри «настоящее изображение» (мем, арт, типографика) или это просто текст (твит, заметка). Оригинал сохранять всегда.
- **Альбомы**: несколько фото приходят отдельными апдейтами с общим `media_group_id`. Буферизовать с задержкой 1–2 сек, обработать пачкой, один ответ на альбом.
- Картинки, отправленные как файл (`document` с image/*), обрабатывать так же.

### 3.2 Голосовые и аудио (Telegram)
- `voice`, `audio`, `video_note` (кружочки) → скачать → транскрипция (язык не фиксировать) → `raw_text`.
- Для `video_note` и видео: извлечь аудио через ffmpeg.
- Длинные голосовые (> ~10 мин) резать на куски по лимиту API.

### 3.3 Пересланные сообщения
- Брать `forward_origin`: от кого / из какого канала и **исходную дату** → `origin_detail`, `occurred_at`.
- Если пересланное — голосовое или фото, идёт по своему конвейеру, плюс метаданные пересылки.
- Пачку пересланных подряд (выделила несколько и переслала) склеивать в одну запись, если они от одного отправителя и пришли в пределах пары секунд. Это обычно одна мысль.

### 3.4 Instagram (обходной путь)
Instagram не даёт пересылать голосовые наружу. Варианты:
- **Запись экрана**, пока голосовое играет → отправить видео боту → идёт как видео (аудио извлекается, транскрибируется). `origin = 'instagram'` бот ставит, если в подписи есть «инст» / «ig», иначе спрашивает одной кнопкой.
- Позже, по желанию: импорт выгрузки переписок Instagram (Настройки → Скачать информацию) отдельным скриптом.

### 3.5 TikTok (Фаза 1b)
Нажимаешь «Поделиться» в TikTok → ссылка боту.
1. yt-dlp скачивает видео + метаданные (подпись, автор, дата).
2. ffmpeg достаёт аудио → транскрипция.
3. **Текст с экрана**: ffmpeg вытаскивает 4–8 кадров → vision. Важно для рецептов: ингредиенты часто только написаны в кадре, а не произнесены.
4. Claude определяет тип: рецепт → `structured = {ingredients, steps}`; мысль, смешинка, совет и т.п.
5. Сохраняется: ссылка, транскрипт, подпись, автор, дата, разбор и **3 ключевых кадра** (чтобы помнить, что это было, даже если ролик удалят). **Само видео не хранится**: скачивается во временную папку только для разбора и удаляется сразу после.

**Если скачивание сломалось** (TikTok что-то поменял): сохранить ссылку + что удалось достать, `status = 'pending_media'`, повторить попытку позже (cron раз в сутки, после `yt-dlp -U`).

Та же логика годится для Instagram Reels и YouTube Shorts по ссылке.

**Длинные видео YouTube.** yt-dlp сначала пробует забрать субтитры (авторские или автоматические) — это дешевле транскрипции. Нет субтитров → аудио → транскрипция. Для длинных видео: `summary` = главные мысли с таймкодами, полный текст в `raw_text`, эмбеддинги по кускам (`item_chunks`, §3.6). Разбор зацепа (§3.9) для длинных видео — только по первой минуте.

**Instagram, который сейчас пересылается себе на второй аккаунт.** Новое — вместо пересылки на второй аккаунт: «Поделиться» → «Копировать ссылку» → вставить в бот (или «Поделиться» → Telegram). Старое, уже накопленное в переписке со вторым аккаунтом: выгрузка данных Instagram (Настройки → Центр аккаунтов → Скачать информацию, формат JSON, раздел «Сообщения»). В ней, насколько известно, есть ссылки на пересланные рилсы. Скрипт `import_instagram_dm` берёт переписку со вторым аккаунтом, вытаскивает ссылки и прогоняет через конвейер. Формат проверить на реальном файле.

**Основной способ — пересылать в бот, а не жать «Сохранить» в TikTok.** Избранное TikTok — закрытый список без поиска и разбора, и читать его программно официально нельзя. «Поделиться» → Telegram → бот — это те же 2–3 тапа.

**Опционально, позже: импорт избранного TikTok.** Для того, что уже накоплено в «Избранном» (или если иногда удобнее нажать «Сохранить»): TikTok отдаёт выгрузку данных (Настройки → Аккаунт → Скачать данные), в ней, насколько известно, есть список избранных видео со ссылками. Скрипт `import_tiktok_favorites` берёт ссылки и прогоняет каждую через тот же конвейер. Проверить формат выгрузки на реальном файле.

### 3.6 Чаты с ИИ (Gemini, Claude, Qwen)
Два пути:
- **Вставка текста** (`chat_paste`): скопировала кусок разговора → вставила в бот. Длинный текст (> ~4000 символов) Telegram режет на несколько сообщений: склеивать идущие подряд в пределах нескольких секунд.
- **Share-ссылка** (`chat_link`, Фаза 1b): ссылки вида `gemini.google.com/share/…`, `share.gemini.google/…`, `chat.qwen.ai/s/…`, `claude.ai/share/…`. Обычный HTTP-запрос не работает: страницы рендерятся через JavaScript. Открывать через **Playwright**, ждать загрузки, забирать текст страницы.
  - Для длинных разговоров: `summary` = выжимка решений и выводов (не пересказ всего), полный текст хранить в `raw_text`, эмбеддинги — по кускам (chunking ~1500 токенов) в отдельной таблице `item_chunks`, если поиск по длинным чатам начнёт промахиваться.
  - Если страница не открылась: сохранить ссылку, ответить «не смогла открыть, вставь текст».

### 3.7 Apple Notes и просто текст
- Из Заметок: «Поделиться» → Telegram → бот. Приходит как текст или файл. Обрабатывать как `text`, `origin = 'apple_notes'`, если понятно по формату, иначе `other`.
- Обычное сообщение, написанное боту = мысль (`text`).

### 3.8 Произвольные ссылки
Статья, пост, сайт → забрать заголовок и основной текст (обычный fetch, при неудаче Playwright) → суть и теги.

### 3.9 Видео ради зацепа (тикток, рилс, шортс)
Часто видео сохраняется не ради информации, а ради **того, как оно сделано**: сочетание картинки и звука, контраст, странность, то, что цепляет глаз. Пример: рыжий белый парень в арабской одежде, в дорогой машине, рассуждает про бизнес. Ценность в образе, который не вяжется с темой, а не в его словах про бизнес.

**Главное в этом разборе — не «чем зацепить» вообще.** Интересны решения, которые **выглядят случайными или естественными, но, скорее всего, продуманы**. Зритель никогда не подумает, что это спланировано. Странный кастинг, «неудачный» свет, оговорка, будто бы случайный предмет в кадре, снято «как на телефон», нелепая одежда. Бот должен вытаскивать именно это: что кажется случайностью → какое решение за этим, вероятно, стоит → как это решение спрятано.

Модель не может знать, что было задумано на самом деле. Это **гипотезы**, и в ответе они должны так и звучать («скорее всего», «похоже на»), а не как факты.

Поэтому для каждого видео модель отдельно отвечает на вопрос **«в чём здесь ценность: в информации или в форме?»** → `save_reason`. Если `hook` / `funny` / `controversial` / `aesthetic` / `mixed`, делается разбор зацепа:

1. Видео целиком (со звуком) отправляется в Gemini (§1).
2. Промпт просит разобрать **первые 1–3 секунды отдельно** от всего видео и вернуть JSON `hook`. Самые важные поля — `looks_accidental`, `probably_deliberate`, `how_hidden`; остальные — контекст для них:
   ```json
   {
     "looks_accidental": "что в ролике выглядит случайным, естественным, «просто так получилось»",
     "probably_deliberate": "какое решение, вероятно, за этим стоит и зачем (гипотеза)",
     "how_hidden": "чем замаскирована продуманность: небрежная съёмка, «живой» тон, оговорки, бытовой фон…",
     "first_seconds": "что происходит в первые 1–3 сек: кадр, первая фраза, первый звук",
     "visual": "кто в кадре, внешность, одежда, место, предметы, композиция, свет",
     "audio": "голос (интонация, темп, акцент), музыка/трек, звуковые эффекты, тишина",
     "text_on_screen": "надписи, субтитры, их стиль",
     "mismatch": "что с чем НЕ вяжется (образ vs тема, звук vs картинка, ожидание vs реальность)",
     "emotion": "какая реакция задумана: удивление, смех, раздражение, «чё?», зависть…",
     "format": "тип ролика: монолог в камеру, POV, скетч, до/после, ответ на коммент…",
     "edit": "монтаж: темп склеек, зумы, перебивки, длина",
     "why_it_works": "1–2 предложения: почему это останавливает скролл",
     "reusable_move": "скрытое решение в общем виде, без привязки к этому видео: как сделать так же, чтобы тоже выглядело случайным"
   }
   ```
   В промпте запретить общие места вроде «яркий визуал привлекает внимание», «эмоциональный контент вовлекает». Нужны конкретные детали этого ролика.
3. `hook_embedding` считается по `my_note` (если есть) `+ looks_accidental + probably_deliberate + how_hidden + mismatch + reusable_move`. Если `my_note` пришёл после разбора, разбор и эмбеддинг пересчитываются с ним. Тогда похожими окажутся видео, которые цепляют **одним приёмом**, даже если темы у них совсем разные (бизнес, еда, шрифты).
4. Короткий ответ в чат: `🎬 тикток · зацеп: образ не вяжется с темой · сохранено` + кнопки **[инфа] [зацеп] [смешное] [и то и то]**. Кнопки **необязательные**: если ничего не нажать, остаётся догадка модели. Нажала → `save_reason` исправлен. Нужны только на случай, когда модель явно промахнулась.

Можно сразу подсказать боту, написав подпись при отправке: «зацеп», «хук», «за звук», «чё за образ». Тогда модель не угадывает.

**Свой комментарий «почему меня зацепило».** Если сразу после пересылки (в течение ~1 минуты) отправить голосовое или текст, бот не сохраняет его отдельной записью, а прикрепляет к видео как `my_note` (транскрипт). Это самое ценное поле: разбор модели — гипотеза, а `my_note` — твоя реальная причина. При разборе и в `/playbook` `my_note` весит больше, чем догадка модели. Необязательно: без комментария всё работает.

**Рамка:** бот разбирает, почему видео зацепило **тебя** и чем оно полезно тебе. Исследование того, что цепляет **других** (фокус-группы, аудитория), — вне этого бота, относится к проекту личного бренда.

## 4. Поиск (Фаза 2)

### `/ask <вопрос>` (или голосом)
- `/ask что я говорила про видео для парня?` → эмбеддинг вопроса → топ-15 ближайших записей (+ фильтр по дате / типу, если в вопросе есть «в сентябре», «рецепт», «из тиктока») → Claude отвечает **только по найденному**, коротко, со ссылками на записи и датами.
- **Голосовой вопрос:** отправить `/ask`, затем голосовое → оно идёт как запрос, а не сохраняется. Всё, что прислано без `/ask`, — это сбор.
- Если ничего не нашлось — так и сказать, не выдумывать.

### Простые фильтры
- `/recent` — последние 10 записей.
- `/type recipe` — все рецепты (и другие типы).
- `/from tiktok` — всё из источника.
- `/hooks` — все видео, сохранённые ради зацепа, с одной строкой `reusable_move` у каждого.
- `/ask` понимает и вопросы про зацепы: «чем цепляют в роликах про деньги?», «покажи, где смешное из-за звука». Для таких вопросов поиск идёт по `hook_embedding`.

### Зеркало в Google-таблицу (по желанию)
Бот дописывает строку в Google Sheet при каждой записи: дата, тип входа, тип контента, суть, ссылка. Только витрина, чтобы глазами листать. Хранение и поиск — в Supabase.

## 5. Темы и компас (Фаза 3)

### Кластеризация (cron раз в сутки или команда `/recluster`)
1. Выгрузить все `embedding`.
2. HDBSCAN → `theme_id` каждой записи (шум = без темы).
3. По каждому кластеру — вызов Claude: `label`, `synthesis`, `next_step`.
4. Пересчитать:
   - **recurrence** — сколько и как регулярно докидываешь;
   - **recency** — `last_added_at`;
   - **momentum** — темп прироста за последние 2–3 недели vs обычный;
   - **status**: `recurring` (часто, но ровно) / `active` (растёт сейчас) / `dormant` (затухла).

### Команды
- `/themes` — топ тем.
- `/lost` — когда непонятно, чем заняться. Две полки:
  - **«к чему ты возвращаешься»** — по recurrence;
  - **«что созрело для действия»** — растущие свежие темы (high momentum).
  Для каждой: название, сквозная линия, следующий шаг.
- `/theme <название>` — записи темы + шаг.

### Библиотека приёмов (из зацепов)
Отдельная кластеризация по `hook_embedding` только для видео с `save_reason ≠ 'info'`. Получаются группы **по скрытому приёму**, а не по теме: например «странный кастинг, который выглядит как просто человек», «намеренная небрежность съёмки», «образ не вяжется с темой», «"случайный" предмет в кадре».
- `/playbook` — список приёмов. Для каждого: название, сколько у тебя примеров, 2–3 ссылки на лучшие, и как этот приём можно применить у себя (для OFST, клиентов, личного бренда).
- Это не «тренды», а твоя личная библиотека того, что цепляет **тебя**. Работает на объёме: имеет смысл от ≈30 таких видео.

**Важно:** частое ≠ то, что стоит делать. Иногда крутишься вокруг темы, потому что застряла. Поэтому recurrence и momentum держать **раздельно**, компас должен различать «залипание» и «живой импульс».

## 5.0 Направления, темы и пересортировка без ручной работы
У каждой записи три независимых поля:
- `content_type` — **что это**: совет, рецепт, идея, смешное, референс…
- `project` — **к какому направлению жизни**: список из конфига (направления пользователя: Lock in / деньги, OFST, обмен, дропшиппинг, сайты на продажу, UMPRUM, личный бренд, арт и портфолио, другой бизнес, здоровье и быт, státnice, разное). Можно несколько.
- `theme` — **о чём**: темы интересов (маркетинг и продвижение, типографика, дизайн-референсы, деньги и бизнес, код и инструменты, рецепты, смешное…). Плюс свободные теги.

**`/resort <как хочу>`** — описываешь словами новую структуру («раздели маркетинг на хуки и воронки», «добавь направление X»). Бот предлагает новый список, после подтверждения **пересортировывает все записи сам** по уже сохранённой сути (видео заново не скачиваются, это дёшево). Ручной пересортировки никогда нет.

**Новые ветви сами:** раз в неделю бот смотрит записи в «разное» и с низкой уверенностью темы и предлагает: «похоже, появилась новая тема — <название>, 12 записей. Добавить?». После ≈100 записей это подкрепляется кластеризацией (§5).

**Папки:** выгрузка (§5.1) раскладывает заметки по папкам `Направление / Тема /` — навигация как в Notion, плюс граф как в Obsidian. Папки пересобираются при каждой выгрузке, руками не сортируются.

## 5.1 Смысловое дерево в Obsidian (дешёвая замена UI)
Скрипт `export_obsidian` выгружает базу в папку-хранилище Obsidian:
- одна заметка `.md` на запись: суть, «Зачем мне», английский перевод, теги, ссылка на оригинал, разбор зацепа;
- одна заметка на тему (хаб), каждая запись ссылается на свою тему `[[Тема]]`;
- в каждой записи ссылки `[[…]]` на 3–5 ближайших по смыслу записей (по эмбеддингу);
- для видео — отдельные хабы приёмов из `/playbook` (§3.9), чтобы зацепы тоже складывались в граф.
Граф Obsidian (Graph view) показывает кластеры сам, без своего фронта. Запуск по команде или раз в день. Хабы тем делают граф читаемым, иначе это просто облако точек.

## 5.2 Вирусность
При скачивании yt-dlp отдаёт метаданные: просмотры, лайки, комментарии, репосты, дату публикации. Сохранять их в `raw_meta.stats` для TikTok / Reels / Shorts / YouTube. Тогда у каждого видео есть два независимых признака:
- **цепляет ли тебя** — `save_reason`, `my_note`;
- **зашло ли людям** — просмотры относительно подписчиков автора и возраста ролика.
`/playbook` показывает по каждому приёму обе стороны: «цепляет тебя и залетело» / «цепляет тебя, но не залетело». Это не исследование аудитории, а цифры, которые платформа и так показывает публично.

## 5.2a Авторы
Для каждого видео и поста сохранять автора: имя, ник, ссылку на профиль, платформу, число подписчиков на момент сохранения (нужно для «залетело относительно аудитории», §5.2). Поле `author` уже есть — расширить до jsonb или вынести в таблицу `authors` (один автор → много записей).
- В карточке: `@ник` со ссылкой на профиль.
- Потом: `/author <ник>` — всё сохранённое от автора; «кого ты сохраняешь чаще всего»; в блоге OFST (§5.3) — всегда указывать автора и ссылку на оригинал.

## 5.3 Блог OFST из архива
Основной формат блога — **просто полезные ссылки**: «посмотрите это видео» + ссылка на оригинал (+ при желании одна строка от себя). Не перезаливать чужие видео.
- Кнопка в карточке **«в блог»** → флаг `for_blog = true` (поле добавить в `items`).
- `/blog` — список отмеченного; позже выгрузка списка для страницы блога на сайте OFST.
- Потом, по желанию: подборки — слияние нескольких видео на одну тему в общую суть + твои дополнения.

## 5.4 Второй пользователь и языки интерфейса (после того, как бот работает у владельца)
Цель: дать бота второму человеку (родной язык — чешский). Языки интерфейса: **русский, чешский, английский, вьетнамский**.
- **Несколько пользователей:** whitelist → таблица `users` (telegram_user_id, язык, свой канал-архив, свои направления и темы). Во всех таблицах `user_id`, каждый запрос фильтруется по нему: никто не видит чужие записи.
- **Свой канал-архив и свои направления** у каждого; список тем по умолчанию общий, дальше у каждого свой `/resort`.
- **Языки:** все тексты бота — через файлы переводов (`ru`, `cs`, `en`, `vi`), выбор `/lang`. Суть и «Зачем мне» Gemini пишет на языке пользователя + английский (§ перевод). Подход к i18n можно взять из бота-магазина (там уже пять языков).
- **Расходы:** запросы второго пользователя идут через тот же ключ Gemini — учитывать лимиты и стоимость; на бесплатном тарифе Google может использовать данные для обучения.

## 7. Безопасность и приватность
- **Один пользователь**: захардкодить свой `telegram_user_id`, всех остальных молча игнорировать.
- Все ключи (bot token, ключи моделей, Supabase service key) — в env хостинга, не в коде и не в репозитории.
- В базе будут личные вещи (голосовые, переписки). Supabase: включить RLS, доступ только через service key с сервера. Bucket в Storage — приватный.
- Ссылки на оригиналы в ответах бота — подписанные (signed URL) с коротким сроком.

## 8. Стоимость (порядок величин)
Бот работает на **API-ключах**, а не на подписке Claude. Лимиты и кредиты в приложении Claude на него не влияют: когда в приложении закончились сообщения, бот продолжает принимать, сортировать и отвечать на `/ask`. Платится отдельно, по факту использования.

- Скрин / короткое голосовое / текст: доли цента.
- Тикток: транскрипция + несколько кадров через vision, около цента.
- Длинные голосовые: транскрипция оплачивается поминутно, это основная статья.
- При личном объёме — единицы долларов в месяц плюс хостинг. Точные цены проверить на момент сборки.
