## 0. Что это и зачем

Личный Telegram-бот (сейчас называется «Notes»). Кидаешь в него всё, что раньше сохраняла на телефон или в избранное: тиктоки, рилсы, YouTube, скрины, голосовые, заметки, профили, куски чатов с ИИ. Бот сам достаёт **смысл** (не просто суть, а «зачем это мне»), раскладывает по направлениям и темам, хранит оригиналы в приватном канале-архиве и даёт удобно смотреть и искать всё в мини-аппе «Архив».

Проблема, которую решает: важное разбросано по приложениям, видео не досматриваются, сохранённое теряется, ручная сортировка в Notion/Obsidian никогда не доходит до конца. Здесь сортировки руками нет вообще.

## 3. Данные

### `items` (основное; поля под будущее можно держать пустыми)
- **служебное:** `id`, `user_id`, `status` (`paused` / `queued` / `processing` / `ok` / `pending_media` / `failed`), `created_at`, `occurred_at` (дата публикации оригинала / пересылки), `raw_meta` (что делал каждый шаг, какой путь скачивания сработал).
- **откуда:** `input_kind` (`tiktok` / `reel` / `youtube` / `link` / `screenshot` / `photo` / `voice` / `video` / `video_note` / `text` / `forwarded` / `document` / `profile` / `chat_paste` / `chat_link`), `origin`, `origin_detail`, `source_url`, `tg_message_id`, `tg_file_id`, ссылка на пост в канале-архиве, `thumbnail_path`.
- **дедуп:** `media_hash`, `text_hash` (ссылки нормализуются: убираются `utm`, `_t` и т.п.).
- **автор:** имя, ник, ссылка на профиль, платформа, подписчики на момент сохранения (jsonb или таблица `authors`).
- **цифры:** `raw_meta.stats` — просмотры, лайки, комменты, репосты, дата публикации (на момент сохранения).
- **тексты:** `raw_text` — транскрипт дословно + текст на экране; `transcript_formatted` — тот же транскрипт, оформленный (диалог как диалог с репликами, перечисления пунктами, абзацы); `summary` — суть; `visual_description` — что в кадре.
- **смысл:** `why_me` — «Зачем мне» (1–2 строки) + метки применения (`asset` / `strategy` / `ofst` / `content` / `interesting`); `summary_en` + `why_me_en` — английский всегда.
- **разметка:** `content_type` (что это: совет, рецепт, идея, смешное, референс…), `project[]` (направления), `theme` (о чём), `tags[]`, `value_in[]` (`info` / `visual` / `audio` / `format` / `meta`), `stance` (`like` / `dislike` / `anti_example` / `replicate` / `format_idea` / `seen_before`), `language[]`.
- **содержимое:** `structured` (списки: фильмы, книги, места, инструменты; рецепт целиком), `comments_summary`, `caption` (оригинальное описание полностью).
- **твоё:** `my_note` (голос/текст «почему зацепило» — прикреплённый в течение ~1 мин после пересылки или позже из Review; весит больше догадки модели), `for_blog`, `review_status` (`new` / `later` / `done`; по умолчанию `new`).
- **зацепы:** `hook` (jsonb: `looks_accidental`, `probably_deliberate`, `how_hidden`, `first_seconds`, `visual`, `audio`, `text_on_screen`, `mismatch`, `emotion`, `format`, `edit`, `why_it_works`, `reusable_move`), `hook_embedding`.
- **поиск:** `embedding vector(1536)`, `theme_id` (под будущую кластеризацию).

### Другие таблицы
- `themes` — под кластеризацию (label, synthesis, next_step, recurrence, momentum, status).
- `users` — telegram_user_id, язык, свой канал-архив, свои направления и темы, `display_name` (заголовок мини-аппа, §8).
- `settings` — списки направлений/тем, `/notify` и т.п.

### Направления (`project`, можно несколько)
Lock in / money · OFST · exchange · dropshipping · sites for sale · UMPRUM · personal brand · art & portfolio · other business · health & daily · státnice · misc.

### Темы (`theme`)
typography & fonts · design references · hooks & marketing · money & business ideas · code & tools · study · recipes · funny · misc.

Владелец хочет всё на английском и «health & daily» разделить (живот, голова, спорт, еда + предложения модели), а также выделить сквозную тему **sales** — через починенный `/resort` (§11, п.13).

## 4. Входы

| Вход | Как |
|---|---|
| **TikTok** (главное) | Цепочка скачивания: yt-dlp → TikWM → embed → oEmbed (только подпись и автор). Слайдшоу — картинки через gallery-dl / TikWM. Видео целиком в Gemini. Не скачалось → `pending_media`, повтор раз в сутки после `yt-dlp -U`. |
| **Reels / Shorts** | Тот же код. Instagram часто требует вход → `pending_media` со ссылкой. |
| **YouTube** | Gemini принимает ссылку на публичное видео напрямую (проверить); иначе субтитры через yt-dlp. Длинные — суть с таймкодами, разбор формата только по первой минуте. |
| **Скрины** | По одному и альбомами до 10 (`media_group_id`, буфер 1–2 с, один ответ на пачку). |
| **Голосовые, кружочки, аудио, видео** | Файл в Gemini. Через локальный `telegram-bot-api` — до 2 ГБ (облачный Bot API — только 20 МБ, из-за этого не проходили видео с телефона). Больше 2 ГБ → «слишком большой». Видео с телефона без ссылки → `source_url` пустой, это нормально. |
| **Текст, пересланное** | Пересланное: автор и исходная дата из `forward_origin`. Длинные вставки (> ~4000 символов) склеивать. |
| **Профили** | Ссылка на аккаунт Instagram / TikTok / компанию → имя, био, подписчики, человек/компания, `stance` (пример / антипример / хочу так же). Instagram без входа даёт мало — надёжнее **скрин сетки профиля** с подписью «профиль». |
| **Чаты с ИИ** | Вставка текста — сейчас. Share-ссылки (Gemini / Qwen / Claude) — через Playwright, потом. |
| **Apple Notes** | По одной через «Поделиться» — сейчас. Все разом — выгрузка (Exporter / Команды) + скрипт — потом. |
| **Импорт накопленного** (потом) | Выгрузка TikTok (избранное), выгрузка Instagram (переписка со вторым аккаунтом), YouTube «Смотреть позже». Форматы проверить на реальных файлах. |

## 5. Обработка

**Базовый разбор — для каждой записи** (дёшево): `raw_text`, `transcript_formatted`, `summary`, `visual_description` (коротко всегда, подробно если речи мало), `why_me` + метки, английский, `content_type`, `project`, `theme`, `tags`, `value_in`, `stance`, `structured`, `comments_summary`, `language`. Подсказка в подписи («за звук», «формат», «антипример», «зацеп») главнее догадки модели. Ответ — строгий JSON, при ошибке один повтор, потом `failed`.

**`why_me` — не только «полезный совет».** Запись может быть сохранена на мета-уровне: как прикол, пример явления, антипример, «смотри, как люди это делают». Модель должна допускать такое прочтение и не выдавать «это неверно / не применимо». Если есть `my_note` — она решает, модель не спорит.

**Комментарии:** 20–30 топовых через yt-dlp, вместе с видео в Gemini. Не скачались — пропустить.

**Глубокий разбор формата (`hook`) — не для всех:** если `value_in` содержит `format` / `visual` / `audio` / `meta`, если в подписи «формат»/«зацеп», или по кнопке «Разобрать формат». Главное — не «чем зацепить вообще», а **что выглядит случайным, но, вероятно, продумано, и как это спрятано**. Это гипотезы — формулировать «скорее всего», не как факт. Общие фразы («яркий визуал привлекает») запрещены.

**После сохранения:** ближайшая запись по эмбеддингу; близость > 0.9 → «похоже на: <суть>, <дата>». Точный повтор (хэш) → «уже есть: <суть>, <дата>».

**Новая `my_note` к старой записи** (из Review, §8) → запись переобрабатывается по сохранённым тексту и разбору (видео заново не качается): `summary`, `why_me`, метки, `stance`, теги, пост в канале обновляется.

**Надёжность:** при старте зависшие `processing` → `queued`. `/retry` повторяет `failed` и `pending_media`.

## 6. Пост в канале-архиве (ничего не обрезается)

1. **Медиа с короткой подписью** (лимит ~1024): заголовок · `@автор` (ссылка) · дата публикации · направления и темы.
2. **Ответом — карточка текстом** (лимит ~4096): суть · «Зачем мне» · EN · `structured` целиком (рецепт, списки) · «В комментах» · оригинальное описание полностью.
3. **Ответом — транскрипт** (оформленный; .txt, если длинный).

Длиннее лимита → продолжение следующим сообщением по границе абзаца. **Никогда «…».** Старые обрезанные посты и записи без транскрипта/автора исправляет `/reprocess` (берёт оригинал из канала, прогоняет заново; посты, которые бот не публиковал сам, выкладывает заново и присылает список).

## 7. Чат с ботом

- Без постоянной клавиатуры. Кнопка «Меню» → мини-апп «Архив».
- Вместо «принято» — реакция на твоё сообщение: 👀 в работе · ✅ готово · ⚠️ ошибка.
- Итог в чат не присылать. В чат — только короткие ошибки и, если включено `/notify`, одна строка со ссылкой на пост.
- Команды в меню: `/pause`, `/resume`, `/retry`, `/resort`, `/reprocess`, `/lang`, `/notify`, `/help`. Работают и в `обратных кавычках`.

### `/pause` и `/resume` (экономия)
`/pause` — новые записи принимаются как обычно: ссылка и метаданные сохраняются, видео скачивается (yt-dlp — бесплатно), оригинал уходит в канал-архив. Но в Gemini ничего не отправляется: статус `paused`, реакция ⏸. `/resort`, `/reprocess`, `/retry`, мини-апп работают по уже обработанным записям. `/resume` → все `paused` становятся `queued` и обрабатываются по очереди. Настройка своя у каждого пользователя (`users`); владелец может поставить на паузу любого.

### `/resort`
Любая формулировка, любой язык, несколько указаний сразу: разделить, объединить, переименовать, перевести все названия, добавить тему, «выделить X из всего» (сквозная тема), «предложи сам». Gemini возвращает полную новую структуру + список изменений → бот показывает изменения и сколько записей переедет → [Применить] [Отмена] → пересортировка всех записей по сохранённой сути (видео не качаются заново). Ошибка — с понятной причиной, сырой ответ модели в лог.

Раз в неделю бот сам предлагает новые ветви из «misc» и записей с низкой уверенностью.

## 8. Мини-апп «Архив»

- **Заголовок:** не «Архив», а имя или ник пользователя (из Telegram `initData`; можно поменять → `users.display_name`).
- **Вкладки:** Feed · Topics · **Review**.
- **Лента (Feed):** карточки (превью, заголовок, @автор, дата, теги), поиск, фильтры — направление (Area), тема (Topic), тип (Type), `value_in`, `stance`, источник, «в блог», `review_status`.
  - Каждый фильтр по тапу открывается **на весь экран** списком значений с количеством.
  - Повторный тап по выбранному значению **снимает выбор** (= All). Кнопка All остаётся.
- **Поиск:** одна строка, по смыслу + по словам.
- **Карточка:** всё из поста + разбор формата + свёрнутый оформленный транскрипт.
  - Тап по превью → **пост в канале-архиве**.
  - Кнопка **Source** → оригинал (TikTok / IG / YT / ссылка); скрыта, если `source_url` пуст.
  - Кнопки «в блог», 👍 / 👎, «на потом».
- **Review:** одна запись на экран, по очереди (сначала `new`, потом `later`). Смотришь → 👍 / 👎 (`stance`), «досмотреть / на потом» (`review_status = later`), «готово» (`done`), 🎙 «почему сохранила» → `my_note` → переобработка (§5). Голос — запись в мини-аппе (MediaRecorder); если микрофон в WebView Telegram недоступен (iOS) — кнопка открывает чат с ботом, ответ голосовым на его сообщение прикрепляется к записи.
- **Темы / направления:** список с количеством.
- **Стиль:** как у Telegram — цвета из `themeParams`, `setHeaderColor` / `setBackgroundColor` в цвет фона (иначе системные ✕ и ⋯ в шапке белые и выбиваются).
- **Устройство (бесплатно):** Vite + React на статическом хостинге (Vercel / Cloudflare Pages); данные через Supabase Edge Function с проверкой Telegram `initData`; service role только в функции; поиск по смыслу там же. Работает, даже когда Мак выключен. Превью-кадр (jpg ~50 КБ) в Supabase Storage.
- **Дизайн:** задаёт владелец (референс / Figma); без него — спокойный тёмный минимализм, крупная типографика.
- **Граф — потом** (§10).

## 9. Несколько пользователей и языки

Для второго пользователя (родной язык чешский). Таблица `users`, `user_id` везде, каждый видит только своё; добавляет только владелец (`/adduser <id>`); у каждого свой канал-архив (определяется по тому, кто добавил бота) и свои направления/темы. Интерфейс: ru · cs · en · vi (файлы переводов, `/lang`); суть и «Зачем мне» на языке пользователя + английский. Подход к i18n — как в боте-магазине. Расходы на Gemini — считать, когда второй пользователь начнёт пользоваться.

## 10. Потом (по порядку)

1. `/ask` — вопрос текстом или голосом по всей базе, ответ только по найденному, со ссылками.
2. Импорт накопленного: избранное TikTok, Instagram-переписка, YouTube «Смотреть позже», Apple Notes разом.
3. `/playbook` — библиотека приёмов из зацепов: кластеры по `hook_embedding`, для каждого «цепляет тебя и залетело / не залетело» (по `stats` относительно подписчиков автора). От ≈30 видео-зацепов.
4. Темы сами по себе (HDBSCAN по эмбеддингам) и компас `/lost`: «к чему возвращаешься» (recurrence) отдельно от «что созрело» (momentum). От ≈100 записей.
5. Граф: в мини-аппе или выгрузкой в Obsidian (папки «направление / тема», хабы тем, связи с 3–5 ближайшими).
6. Утреннее повторение: 3 старые записи, которые давно не открывались.
7. Блог OFST: кнопка «в блог» → список ссылок «посмотрите это» + автор + ссылка на оригинал (не перезаливать). Позже — подборки из нескольких видео с дополнениями.
8. Нарезка видео: «вырежи с 0:12 до 0:30» / «оставь суть, убери лишнее» (голосом или текстом) → ffmpeg на Маке → новый клип в канал, привязан к записи.
9. «Живое» превью в карточке: немой клип ~5 с (~300 КБ) в Storage вместо кадра. Только если не перегружает.
10. Заметка без сроков: публичный Telegram-канал из отобранного архива и его монетизация (реклама Telegram от 1000 подписчиков, Stars, прямые рекламные посты) — отдельный проект, вне бота.

Не делаем: удаление из базы, Google Sheets, Railway (пока), постоянную клавиатуру.
