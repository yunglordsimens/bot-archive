# bot-archive

Telegram-бот-архив (MVP): ссылка / скрин / голосовое → «принято» → Gemini достаёт суть → ответ редактируется на итог.
Стек: Node 22 + grammY (long polling) · Supabase Postgres + pgvector · Gemini · yt-dlp + gallery-dl. Работает на Маке.

Документы: `MVP.md` (что делает первая версия) и `SPEC.md` (полная спека на будущее).

## 1. Подготовка (один раз)

1. `cp .env.example .env` → открыть `.env` и вписать `BOT_TOKEN`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`.
   Остальное уже заполнено или имеет значения по умолчанию — описание каждой переменной в `.env.example`.
2. Открыть бота в Telegram и нажать **/start**. Без этого бот не может написать тебе первым.

Запускать **только один** вариант ниже. Два бота с одним токеном одновременно → ошибка `409 Conflict`.

## 2а. Запуск через Docker Desktop (основной)

Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/). В его настройках: General → **Start Docker Desktop when you sign in**.

```bash
cd bot-archive
./scripts/start-docker-mac.sh
```

Скрипт собирает образ (Node + yt-dlp + gallery-dl), запускает бота в фоне и показывает логи, пока Мак держится бодрым.
`Ctrl+C` закрывает логи и снимает запрет на сон; бот в контейнере продолжает работать, пока Мак не уснёт.

Полезное:
- логи: `docker compose logs -f`
- перезапуск после изменений в коде или `.env`: `docker compose up -d --build`
- остановить: `docker compose down`

Контейнер с `restart: unless-stopped` сам поднимается после перезапуска Docker Desktop.

## 2б. Запуск без Docker (Node + Homebrew)

```bash
brew install node yt-dlp gallery-dl ffmpeg
cd bot-archive
npm ci
./scripts/start-mac.sh
```

Бот работает, пока открыто окно терминала; если упадёт — скрипт сам перезапустит его через 10 секунд. Остановить — `Ctrl+C`.
yt-dlp обновляется сам раз в сутки (`brew upgrade yt-dlp`), когда есть ссылки, которые не скачались.

### Обновить код
Остановить бота (`Ctrl+C`), затем в папке бота: `bash scripts/update.sh` и снова `bash scripts/start-mac.sh`. Файл `.env` не трогается.

## 3. Чтобы Мак не засыпал

Оба скрипта запускают `caffeinate -ims`: Мак не уходит в сон, пока бот работает (экран при этом гаснуть может).
- `-i` — запрет сна по бездействию, `-s` — запрет сна системы при питании от сети, `-m` — диск не засыпает.
- **Крышку MacBook не закрывать**: с закрытой крышкой Мак засыпает всё равно (кроме режима с внешним монитором и питанием).
- Надёжнее держать на зарядке. Дополнительно: Системные настройки → Аккумулятор → Параметры → «Предотвращать автоматический переход в режим сна при питании от сети, когда дисплей выключен».

Пока Мак спит, бот не отвечает, но ничего не теряется: Telegram хранит сообщения до суток, бот заберёт их после пробуждения.

## 4. Канал-архив

1. Создать приватный канал → Управление каналом → Администраторы → Добавить администратора → найти бота → право **«Публикация сообщений»** включено → Сохранить.
2. Бот (должен быть запущен) пишет **тебе в личку с ботом**: `🗄 канал-архив подключён: <название> (<id>)`.
   - Если ты ещё не нажимала /start — это же сообщение появится **в самом канале** с просьбой нажать /start.
   - Если бот был админом ещё до первого запуска (или прошло больше суток) — при старте он пишет `🗄 канал-архив не подключён…`. Тогда убрать бота из админов и добавить заново.
3. При каждом запуске бот проверяет, что он всё ещё админ канала, и пишет в личку, если нет.

## Несколько пользователей и языки (SPEC §5.4)

- Пользователи — таблица `users`. Добавить может только админ (владелец из `OWNER_ID`): `/adduser <telegram_id> [ru|cs|en|vi]` (без языка — чешский). Список: `/users`. Остальным бот молча не отвечает.
- Новый пользователь: открыть бота → /start → создать свой приватный канал → добавить бота админом с правом публикации. Бот сам поймёт, чей это канал (по тому, кто добавил), и напишет «канал-архив подключён» на языке пользователя.
- У каждого: свои записи (все запросы фильтруются по `user_id`, чужую запись даже по кнопке не открыть), свой канал-архив, свой язык (`/lang`: русский, čeština, English, Tiếng Việt), свои направления (`/projects работа, учёба, хобби` — последнее «разное» добавляется само). Темы по умолчанию общие, на языке пользователя.
- Суть, «Зачем мне», теги, названия списков Gemini пишет на языке пользователя; английская версия делается всегда (для англоязычных — не дублируется).
- Повторы считаются у каждого отдельно. `/retry` и `/reprocess` трогают только свои записи.
- Переводы интерфейса — `src/i18n/{ru,cs,en,vi}.ts`; компилятор проверяет, что в каждом языке есть все строки.

## Mini App «Архив» (SPEC §6.0)

- Кнопка **«Архив»** слева от поля ввода в чате с ботом: лента (новые сверху), фильтры (направление, тема, тип, ценность, отношение, источник, «в блог»), поиск по смыслу и по словам, карточка записи целиком, экран «Темы» со счётчиками.
- Работает и при выключенном Маке: фронт на Vercel (`miniapp/`, Vite + React), данные — через Supabase Edge Function `archive` (`supabase/functions/archive`). Функция проверяет подпись Telegram (`initData`), пускает только пользователей из `users` и отдаёт только их записи. Ключ service role — только внутри функции.
- Поиск по смыслу: в Supabase → Edge Functions → Secrets добавить `GEMINI_API_KEY` (тот же ключ, что в `.env`). Без него работает только поиск по словам.
- Превью: при обработке бот сохраняет один кадр (jpg ~50 КБ) в Supabase Storage (`previews`, приватный). Для старых записей кадры делаются сами в фоне после запуска бота.
- Бот при запуске записывает свой id в `settings.bot_id` (по нему функция проверяет подпись) и ставит кнопку «Архив» (`MINIAPP_URL` в `.env`, по умолчанию уже заполнен).
- Обновить фронт: `cd miniapp && npm i && npm run build` → задеплоить `miniapp` на Vercel.

## Чат с ботом

- Постоянной клавиатуры нет (у старых — пропадёт после /start). Кнопка «Меню» = «Архив». В списке команд: /retry /resort /lang /notify /help. Остальные (/recent /project /theme /type /status /reprocess /projects) работают, если набрать.
- `/resort <как хочу>` — на любом языке, несколько указаний сразу: разделить, объединить, переименовать, перевести все названия, добавить тему, «выдели X со всего» (сквозное направление поверх остальных), «предложи сам». Можно в `обратных кавычках`. Бот показывает новую структуру, список изменений и «Переедет: N из M» (переименование не считается переездом) → ✅ Применить → записи пересортировываются по сохранённой сути (видео не качаются), подписи постов в канале обновляются. Если не вышло — понятная причина в чате, сырой ответ модели — в Терминале. Неизвестные /команды в архив не сохраняются.
- Вместо «принято» — реакция на твоё сообщение: 👀 в работе → 👌 готово, 🤷 ошибка, 🤝 повтор. (✅ и ⚠️ Telegram ботам ставить не даёт.)
- Итог в чат не приходит — всё в канале-архиве. В чат: только ошибки (коротко, с кнопкой 🔁) и «видео не скачалось». С `/notify` → «Присылать» — после каждого сохранения одна строка со ссылкой на пост и кнопками карточки (Подробнее, EN, ✏️, 🎬).
- Три поля у записи: тип (что это), направление (можно несколько; свои — `/projects`), тема (о чём).
- /retry — повторить записи с ошибкой и без видео. Если Gemini перегружен, бот сам повторяет через 5/10/15 мин; полный текст ошибки — в Терминале (`item N failed …`) и в колонке `items.error`.
- Пост в канале-архиве из нескольких сообщений, ничего не обрезается: (1) медиа с короткой подписью — заголовок · @автор (ссылка) · 📅 дата оригинала · направления/тема/тип; (2) ответом — карточка текстом: суть, 💭 Зачем мне, списки и рецепт целиком, 💬 комментарии, 🇬🇧 EN, 📝 описание из-под видео полностью (если длинно — несколько сообщений, деление по абзацам/пунктам); (3) ответом — транскрипт (.txt, если длинный). Старые посты приводит к этому виду /reprocess.
- У записи: `raw_text` (транскрипт), `summary` (суть), `visual_description` (что в кадре), `value_in` (инфа/картинка/звук/формат/мета), `stance` (нравится/антипример/хочу повторить/идея формата/уже видела…). Слова в подписи («за звук», «формат», «антипример», «хочу так же») главнее догадки модели; поправить — кнопка ✏️.
- Глубокий разбор формата (§3.9) — только если ценность в формате/картинке/звуке/мета, в подписи «формат»/«зацеп», или кнопка 🎬 Разобрать формат.
- Топ-комментарии (до 25) идут в Gemini вместе с видео; полезное — строкой «💬 В комментах».
- Профили: ссылка на tiktok.com/@…, instagram.com/…, youtube.com/@… или скрин сетки профиля с подписью «профиль».
- /reprocess — перепройти старые записи в этот формат (оригинал берётся из канала, Gemini заново, пост переписывается; если пост изменить нельзя — выкладывается заново, бот присылает список). `/reprocess all` — все записи, `/reprocess 12` — одну.
- В каждой карточке «🗄 в архиве» — ссылка на сообщение в канале-архиве (у ссылок и текстов туда пишется текстовая карточка).
- Каждая запись: «принято» → ⬇️ скачиваю / 🔎 читаю → 🧠 разбираю → итог.
- 📊 Статус: работает ли бот, канал-архив, очередь, ошибки; кнопки 🔄 Обновить и 🔁 Повторить ошибки.
- У неудавшейся записи — кнопка 🔁 Повторить.
- Карточка записи — одна строка. Кнопки: 📖 Подробнее (суть 3–5 строк, пункты, ингредиенты, шаги, списки фильмов/книг/мест…), 📜 Транскрипт (длинный — файлом .txt), 🇬🇧 EN (перевод по запросу, сохраняется).
- Для TikTok / Reels / Shorts / YouTube в `raw_meta.stats` сохраняются просмотры, лайки, комментарии, репосты, дата публикации и подписчики автора на момент сохранения (SPEC §5.2).
- Если запись по смыслу очень близка к уже сохранённой (близость > `SIMILAR_THRESHOLD`, по умолчанию 0.9) — строка «≈ похоже на: …, дата».

## 5. Проверка TikTok (шаг 0)

`/probe ссылка1 ссылка2 …` (10 тиктоков, из них 2–3 слайдшоу) → по каждой ссылке бот отвечает, какой путь сработал:
`yt-dlp` / `tikwm` / `gallery-dl` / `embed` / `oembed` и что ответил каждый.

## Как устроено

- `src/bot.ts` — приём, whitelist, альбомы (буфер 1,5 с → один ответ), подключение канала-архива, команды `/recent` `/theme` `/type` `/probe`.
- `src/worker.ts` — очередь в `items.status`: `queued → processing → ok | pending_media | failed | duplicate`; `pending_media` повторяется раз в сутки после обновления yt-dlp (до 7 раз).
- `src/fetchers.ts` — TikTok: yt-dlp → TikWM → gallery-dl (слайдшоу) → embed → oEmbed; Reels через yt-dlp; YouTube-субтитры; текст страниц.
- `src/gemini.ts` — единственная точка вызова модели (`GEMINI_MODEL` + `GEMINI_FALLBACK_MODELS`), JSON по схеме, эмбеддинг 1536.
- `src/config.ts` — список тем и типов.
- `supabase/migrations/` — схема БД (уже применена к проекту `bot-archive`). Имена полей — по SPEC.md §2; отличия, где решил MVP, описаны в `002_align_spec.sql`.
- `src/ui.ts` — кнопки, меню тем и типов, статус, повтор.
- `scripts/test-*.ts` — проверки: `test-ui` (два пользователя, языки, изоляция), `test-archive-connect`, `test-channel`, `test-dedup` — офлайн; `test-worker-lang` — с настоящим Gemini (`GEMINI_API_KEY=… npx tsx scripts/test-worker-lang.ts`).
